## 1. 문서 목적

이 문서는 [SCAN 2026 참가·분석 도구 준비 전략](./01_SCAN_2026_PREPARATION_STRATEGY.md)의 분류 체계와 표준 작성 양식을 기준으로, 출제 가능성이 있는 예상문제를 수집·정리한다.

현재 단계의 목적:

1. 분류별로 예상문제를 충분히 확보한다.
2. 문제마다 수동 풀이 단계와 필요 데이터를 정의한다.
3. 반복 작업과 자동화·사람 판단 영역을 분리한다.
4. 이후 기능-문제 행렬과 도구 우선순위 산정의 입력으로 사용한다.

이 문서의 문제는 공식 출제 범위가 아니다. 대부분 **예상**이며, SCAN 2024 문제 성격과 일반적인 온체인 포렌식 과제를 **과거 근거**로 참고한다.

## 5. 예상문제 상세

아래 항목은 전략 문서 9절 표준 양식을 따른다. 주소·해시·금액은 연습용 플레이스홀더이며 실제 대회 데이터가 아니다.

### BASIC-EVM-001

```text
문제 ID: BASIC-EVM-001
문제 분류: 블록체인 기초 / 식별
난이도: 하

문제 설명:
주어진 문자열이 주소, 트랜잭션 해시, 블록 해시/번호 중 무엇인지 판별하고
해당 객체의 기본 속성을 보고하라.

주어진 단서:
- 문자열 집합 (0x로 시작하는 값 여러 개)
- 대상 체인 (예: Ethereum)

요구되는 정답:
- 각 문자열의 유형
- 주소라면 checksum 유효성, TX라면 블록·수수료·from/to 요약

수동 풀이 단계:
1. 길이·접두어로 후보 유형을 나눈다.
2. 탐색기 또는 RPC로 존재 여부를 확인한다.
3. 주소/TX/블록의 핵심 필드를 추출한다.
4. 존재하지 않거나 형식이 틀린 항목을 표시한다.

필요한 온체인 데이터:
- eth_getTransactionByHash, eth_getBlockByNumber/Hash, 주소 코드 유무
필요한 오프체인 데이터:
- 없음
사용 가능한 외부 정보원:
- 블록 탐색기, 공개 RPC

반복 작업:
- 다수 문자열의 유형 판별과 기본 조회
자동화 가능한 부분:
- 형식 검증, 일괄 RPC 조회, 요약 테이블 생성
사람이 판단해야 하는 부분:
- 오탐 문자열의 의도(단서 vs 노이즈), 체인 오지정 여부

정답의 증거:
- RPC/탐색기 원본 필드와 조회 시각
오답 가능성과 예외:
- 다른 체인의 동일 형식 문자열, pending TX
필요한 도구 기능:
- 수집, 증거 보고서
```

### BASIC-EVM-002

```text
문제 ID: BASIC-EVM-002
문제 분류: 블록체인 기초 / 잔액
난이도: 하

문제 설명:
특정 주소의 특정 블록 높이(또는 시각) 기준 네이티브 잔액과
지정 ERC-20 보유량을 계산하라.

주어진 단서:
- 주소 A
- 기준 시각 또는 블록 번호
- 토큰 컨트랙트 목록

요구되는 정답:
- 네이티브 잔액
- 토큰별 보유량(소수 자릿수 반영)
- 사용한 블록 번호

수동 풀이 단계:
1. 기준 시각을 블록으로 변환한다.
2. 해당 블록의 balance를 조회한다.
3. 각 토큰의 balanceOf를 동일 블록에서 조회한다.
4. decimals를 반영해 사람이 읽는 단위로 변환한다.

필요한 온체인 데이터:
- 히스토리컬 balance, ERC-20 balanceOf/decimals
필요한 오프체인 데이터:
- 없음
사용 가능한 외부 정보원:
- archive RPC, 탐색기

반복 작업:
- 다수 토큰·다수 시점 잔액 조회
자동화 가능한 부분:
- 블록 변환, 일괄 잔액 조회, 단위 변환
사람이 판단해야 하는 부분:
- 프록시 토큰, rebase 토큰, 스냅샷 의미

정답의 증거:
- 블록 번호와 raw balance 값
오답 가능성과 예외:
- non-archive RPC, 토큰 decimals 오류
필요한 도구 기능:
- 수집, 증거 보고서
```

### EVM-TOKEN-001

```text
문제 ID: EVM-TOKEN-001
문제 분류: EVM / ERC-20
난이도: 하

문제 설명:
주소 A에서 특정 토큰 T가 빠져나간 첫 전송의 수신자와 수량을 찾아라.
단순 네이티브 전송이 아니라 Transfer 이벤트 기준으로 판단한다.

주어진 단서:
- 주소 A
- 토큰 컨트랙트 T
- 검색 시작 시각

요구되는 정답:
- 수신 주소
- 전송량
- Transfer 로그가 포함된 트랜잭션 해시

수동 풀이 단계:
1. T의 Transfer 로그를 A=from 조건으로 수집한다.
2. 시작 시각 이후 첫 이벤트를 고른다.
3. value와 decimals로 실제 수량을 계산한다.
4. 동일 TX의 다른 로그와 혼동되지 않게 확인한다.

필요한 온체인 데이터:
- 이벤트 로그, 토큰 decimals
필요한 오프체인 데이터:
- 없음
사용 가능한 외부 정보원:
- 탐색기 토큰 전송 탭, 로그 API

반복 작업:
- 로그 수집·시간 정렬·단위 변환
자동화 가능한 부분:
- 로그 필터, 첫 이벤트 선택, 증거 추출
사람이 판단해야 하는 부분:
- fee-on-transfer, 허위 Transfer 이벤트

정답의 증거:
- 로그 index, TX 해시, raw value
오답 가능성과 예외:
- approval만 보고 전송으로 오인, 내부 전송 누락
필요한 도구 기능:
- 수집, 프로토콜 해석, 증거 보고서
```

### EVM-TOKEN-002

```text
문제 ID: EVM-TOKEN-002
문제 분류: EVM / 내부 호출
난이도: 중

문제 설명:
컨트랙트를 경유한 트랜잭션에서 주소 A로 실제 유입된 ETH 금액을
내부 트랜잭션(또는 call trace) 기준으로 복원하라.

주어진 단서:
- 트랜잭션 해시 H
- 관심 주소 A

요구되는 정답:
- A로의 실제 ETH 유입액
- 유입을 만든 call/internal tx 경로 요약
- top-level value만 보면 오답인 이유

수동 풀이 단계:
1. H의 top-level from/to/value를 확인한다.
2. internal transactions 또는 debug_trace를 조회한다.
3. A를 수신자로 하는 value transfer를 합산한다.
4. 실패 call과 성공 call을 구분한다.

필요한 온체인 데이터:
- receipt, internal tx, call trace
필요한 오프체인 데이터:
- 없음
사용 가능한 외부 정보원:
- 탐색기 internal tx, trace API

반복 작업:
- trace 파싱과 주소별 합산
자동화 가능한 부분:
- trace 수집, A 관련 value 집계, 실패 호출 제외
사람이 판단해야 하는 부분:
- delegatecall/selfdestruct 특수 경로의 의미

정답의 증거:
- 각 internal transfer의 from/to/value
오답 가능성과 예외:
- top-level value만 집계, reverted call 포함
필요한 도구 기능:
- 수집, 프로토콜 해석, 증거 보고서
```

### FLOW-EVM-001

```text
문제 ID: FLOW-EVM-001
문제 분류: EVM / 자금 흐름 / 거래소 유입
난이도: 중

문제 설명:
피싱 주소 A에서 빠져나간 50 ETH의 최종 도착지를 찾아라.

주어진 단서:
- 피해 주소 A
- 피해 발생 시각
- 피해 금액 50 ETH

요구되는 정답:
- 최종 도착 서비스 또는 주소
- 실제 이동 금액
- 판단 근거 트랜잭션 목록
```

## 7. 자동화 vs 사람 판단 (은행 공통)

| 자동화에 맡길 영역 | 사람이 유지할 영역 |
|:---|:---|
| 일괄 수집, 필터, 합계 | 미라벨 주소의 실체 |
| N홉 후보 경로 생성 | 여러 후보 중 사건 관련 경로 |
| 알려진 라벨 조회 | 라벨 충돌·오보 판정 |
| 그래프·타임라인 초안 | 동일 주체 단정 |
| 증거 표 생성 | 최종 제출 문장과 불확실성 표현 |
