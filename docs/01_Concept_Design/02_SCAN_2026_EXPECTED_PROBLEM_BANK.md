## 1. 문서 목적

이 문서는 [SCAN 2026 참가·분석 도구 준비 전략](./01_SCAN_2026_PREPARATION_STRATEGY.md)의 분류 체계와 표준 작성 양식을 기준으로, 출제 가능성이 있는 예상문제를 수집·정리한다.

현재 단계의 목적:

1. Draft 2 기준 예상문제 30문항을 확정한다.
2. 문제마다 수동 풀이 단계, 필요 데이터, 완료·부분·실패 조건을 정의한다.
3. 반복 작업과 자동화·사람 판단 영역을 분리한다.
4. 기능-문제 행렬을 도구 우선순위 산정의 입력으로 사용한다.
5. 기본 30문항보다 어려운 실전 스트레스 문제를 별도 Challenge Pack으로 관리한다.

이 문서의 문제는 공식 출제 범위가 아니다. 대부분 **예상**이며, SCAN 2024 문제 성격과 일반적인 온체인 포렌식 과제를 **과거 근거**로 참고한다.

### 3.3 난이도 기준

| 난이도 | 기준 |
|:---|:---|
| 하 | 단일 체인·단일 데이터 유형을 조회하며 결과가 결정적이고 기본 개념으로 검증 가능 |
| 중 | 다단계 추적, 이벤트·trace 해석, 라벨 교차검증 중 하나 이상이 필요하지만 시드와 범위가 명확 |
| 상 | 분산·병합, 복수 체인, 복수 프로토콜, 휴리스틱, OSINT 가설 검증 등 복합 요소가 둘 이상이거나 불완전한 단서로 여러 후보를 배제해야 함 |

### 3.4 검증 필드 스키마

모든 문항 상세 카드는 표준 양식에 더해 아래 필드를 포함한다.

| 필드 | 목적 |
|:---|:---|
| 완료 조건 | 문제를 해결한 것으로 보는 최소·필수 기준 |
| 부분 점수 조건 | 최종 정답에는 못 미치지만 인정할 중간 성과 |
| 실패 조건 | 오답·잘못된 방법·금지된 단정으로 보는 기준 |

공통 최소 기준:

- 요구 필드가 모두 채워짐
- 모든 결론에 TX·블록·출처가 연결됨
- 확정 사실과 추정이 구분됨
- 금액 오차가 허용 범위 이내임(해당 시)
- 동일 입력으로 결과를 재현할 수 있음

금액·가격·수수료 관련 허용 오차는 각 reference fixture에서 raw 단위,
수수료 처리 방식, 가격 정밀도와 함께 명시한다.

### BASIC-EVM-001

```text
문제 ID: BASIC-EVM-001
문제 분류: 블록체인 기초 / 식별
난이도: 하

문제 설명:
주어진 문자열이 주소, 트랜잭션 해시, 블록 해시/번호 중 무엇인지 판별하고
해당 객체의 기본 속성을 보고하라.

주어진 단서:
- 문자열 집합 (0x로 시작하는 값 여러 개)
- 대상 체인 (예: Ethereum)

요구되는 정답:
- 각 문자열의 유형
- 주소라면 checksum 유효성, TX라면 블록·수수료·from/to 요약

수동 풀이 단계:
1. 길이·접두어로 후보 유형을 나눈다.
2. 탐색기 또는 RPC로 존재 여부를 확인한다.
3. 주소/TX/블록의 핵심 필드를 추출한다.
4. 존재하지 않거나 형식이 틀린 항목을 표시한다.

필요한 온체인 데이터:
- eth_getTransactionByHash, eth_getBlockByNumber/Hash, 주소 코드 유무
필요한 오프체인 데이터:
- 없음
사용 가능한 외부 정보원:
- 블록 탐색기, 공개 RPC

반복 작업:
- 다수 문자열의 유형 판별과 기본 조회
자동화 가능한 부분:
- 형식 검증, 일괄 RPC 조회, 요약 테이블 생성
사람이 판단해야 하는 부분:
- 오탐 문자열의 의도(단서 vs 노이즈), 체인 오지정 여부

정답의 증거:
- RPC/탐색기 원본 필드와 조회 시각
오답 가능성과 예외:
- 다른 체인의 동일 형식 문자열, pending TX
필요한 도구 기능:
- 수집, 증거 보고서
완료 조건:
- 요구 필드가 모두 채워짐
- 모든 결론에 TX·블록·출처(또는 동등한 원본 조회 키)가 연결됨
- 확정 사실과 추정이 구분됨
- 동일 입력·동일 데이터 스냅샷으로 결과를 재현할 수 있음
- 각 문자열의 유형 판별이 원본 조회와 일치
부분 점수 조건:
- 일부 문자열만 정확히 식별하고 나머지는 미확인으로 표시
실패 조건:
- 라벨 출처 없이 주소 소유자·서비스를 단정
- 확정 사실과 휴리스틱 추정을 구분하지 않음
- 존재하지 않는 해시를 유효 객체로 보고
- 체인을 잘못 지정한 채 결과를 확정

```

| 자동화에 맡길 영역 | 사람이 유지할 영역 |
|:---|:---|
| 일괄 수집, 필터, 합계, 가격 환산 계산 | 미라벨 주소의 실체 |

| 알려진 라벨·동결 상태 조회 | 라벨 충돌·오보·사칭 판정 |
| 그래프·타임라인 초안 | 동일 주체·믹서 이후 연결 단정 |
| 증거 표 생성 | 최종 제출 문장과 불확실성 표현 |

## 8. 미결정 사항

- 실제 대회 지원 체인과 사전 제공 데이터셋
- 정답 제출 형식(주소, TX, 서술, 복수 정답)
- 외부 API·자동화·AI·상용 툴 허용 범위
- 대표 검증 사례 8개의 실데이터·reference answer
- 데이터 소스 등록부의 1차 등재 범위와 공급자 선정
- 공식 규정·실제 구현 시간 확보 후 기능 우선순위 점수식 가중치 보정
- Draft 2 이후 보류 문항(`CRIME-RANSOM-001`, `BTC-BATCH-001`, `FLOW-PRICE-001`) 편입 여부
- Challenge Pack 10문항의 실제 데이터·시간 제한·reference answer와 승격 우선순위

### 10.4 Challenge Pack Candidate 1

#### 10.4.1 목적과 적용 규칙

Challenge Pack은 기본 30문항의 기능 범위를 바꾸지 않고, 실제 대회에서
발생할 수 있는 규모·불완전 단서·추적 회피·데이터 장애·시간 압박을 검증하는
상급 스트레스 문제군이다.

- 기본 30문항의 하4/중14/상12 통계와 원자적 기능 빈도에는 합산하지 않는다.
- `candidate` 상태에서는 도구 우선순위 점수를 올리는 근거로 사용하지 않는다.
- 실제 공개 데이터, reference answer, 완료·부분·실패 조건을 확보한 뒤
  `challenge fixture`로 승격한다.
- fixture 승격 전에는 합성 데이터로 정답 정확도를 주장하지 않는다.
- AI·휴리스틱 결과는 후보 순위에만 사용하고 확정 사실과 분리한다.
- 대회 규정에서 API·자동화·AI가 제한되면 동일 문제의 수동·offline 경로를
  함께 검증한다.

#### 10.4.2 스트레스 난이도 기준

각 차원은 `0`(없음), `1`(부분), `2`(핵심 장애)로 평가한다.

| 코드 | 난도 차원 | 판단 기준 |
|:---|:---|:---|
| `S` | Scale | 주소·거래·로그 수와 페이지네이션·성능 부담 |
| `A` | Ambiguity | 불완전 단서·복수 후보·정답 경계의 불확실성 |
| `O` | Obfuscation | 분산·재병합·미끼·믹서·CoinJoin 등 추적 회피 |
| `D` | Data failure | archive·trace·API·라벨 누락과 공급자 장애 |
| `I` | Integration | 복수 체인·프로토콜·데이터 유형 결합 |
| `T` | Time pressure | 제한 시간 내 부분 성공·증거 제출 필요 |

총점 8점 이상이고 최소 네 차원이 `1` 이상인 문제만 Challenge Pack에
유지한다. 이 점수는 공식 난이도가 아니라 내부 stress coverage 지표다.
